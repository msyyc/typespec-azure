# AvoidAnonymousTypes migration

## 1. Conclusion and scope

`@azure-tools/typespec-azure-core/no-unnamed-types` provides **partial, not functionally equivalent**, coverage of the [AvoidAnonymousTypes Swagger linter](https://github.com/Azure/azure-openapi-validator/blob/6243cb01c16c7535cd3b8df6f45fbeb3c095ed7f/docs/avoid-anonymous-types.md). It checks authored anonymous types, including implicit HTTP response payloads, rather than reproducing emitted-schema inlining. Named dictionaries, emission-specific `allOf` entries and schema-extension overrides remain outside that policy. The rule applies to ARM and data-plane services and is already enabled in both Azure presets, so the response fix can add warnings without an opt-in. A confirmed historical CustomLocations compatibility failure remains unresolved by this PR; current-head full-population coverage and rollout readiness are unassessed.

## 2. Actual coverage

The historical Swagger comparison assessed **462 successfully compiled ARM projects out of 468**. Six compile failures were excluded from both sides; their 22 Swagger findings remain unassessed. The TypeSpec column below counts the former **response-only** `tsp-lintdiff-local-linter/avoid-anonymous-types` implementation, not every check in the consolidated Core rule. Counts are individual diagnostics across the assessed population, not numbers of projects.

| Count                                                     | Swagger linter | TypeSpec linter |
| --------------------------------------------------------- | -------------: | --------------: |
| Historical raw diagnostics in the 462 successful projects |             10 |               1 |

**Assessed coverage:** all 10 Swagger findings were classified as dictionary-representation differences: three response dictionaries, three nested dictionaries and four dictionary-valued properties literally named `additionalProperties`. The single TypeSpec finding was an anonymous SDK-override response declaration outside the emitted HTTP operation population. Thus these observations establish specific, explained policy differences, **not 10 missed anonymous source declarations or one matched violation**. Focused regressions establish response-model naming behavior, but this corpus does not quantify its prevalence. Comparable violation totals and a coverage percentage are **unassessed**; no common defect identity has been established. Emitted composition/extension cases have source-backed scope analysis but no corresponding corpus frequency estimate.

The later installed-package comparison assessed a different population and question: **469 successful source compiles**, with the complete existing naming rule producing **21 baseline versus 22 candidate warnings**, one added CustomLocations warning and none removed. It did not rerun Swagger or establish equivalence. Neither historical run is relabeled as coverage of the current rule/compiler closure. See [Why diagnostic counts differ](#4-why-diagnostic-counts-differ) and the [pinned populations and receipts](evidence-details.md#assessed-inputs-and-counting).

## 4. Why diagnostic counts differ

Here, `raw / grouped` means reported Swagger diagnostics / distinct project + Swagger-file + JSON-path locations in the historical 462-project comparison. No occurrences collapse in this dataset; grouping does not prove a common actionable defect. The TypeSpec column counts only observed response-only diagnostics attributed to the same check and target/context, not unrelated Core warnings on the same operation.

| Difference (with evidence)                                                                                                  | Swagger diagnostics (raw / grouped) | TypeSpec diagnostics for the same check | Recommended action and rationale                                                                                                                                        |
| --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------: | --------------------------------------: | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Three response dictionaries](evidence-details.md#dictionary-representation-differences)                                    |                               3 / 3 |                                       0 | Preserve supported named `Record<T>` authoring. Exact schema-inlining parity would need a separate policy decision, not a blanket anonymous-model warning.              |
| [Three nested dictionaries](evidence-details.md#dictionary-representation-differences)                                      |                               3 / 3 |                                       0 | Retain the source-naming boundary; do not treat a named generic dictionary as an unnamed declaration.                                                                   |
| [Four dictionary-valued properties named `additionalProperties`](evidence-details.md#dictionary-representation-differences) |                               4 / 4 |                                       0 | Preserve the dictionary policy. These selector matches are not evidence of four anonymous source-model violations; no upstream-bug disposition is claimed.              |
| [CustomLocations SDK override](evidence-details.md#sdk-override-and-compatibility)                                          |                               0 / 0 |                                       1 | Name the authored response or obtain an approved compatibility suppression. No service edit or suppression decision is made here; the known rollout issue remains open. |

The Swagger-higher and TypeSpec-higher findings do not cancel: seven projects contribute 10 Swagger-only findings and one different project contributes one TypeSpec-only finding. Additional [composition/extension differences](evidence-details.md#composition-and-extension-boundary) remain non-equivalent even though this corpus does not quantify them. No current-head full-population comparison was performed for this presentation-only refresh.
