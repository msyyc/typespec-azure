# AvoidAnonymousTypes migration

## 1. Scope

The TypeSpec linter `@azure-tools/typespec-azure-core/no-unnamed-types` is assessed against Swagger linter rule [`AvoidAnonymousTypes`](https://github.com/Azure/azure-openapi-validator/blob/6243cb01c16c7535cd3b8df6f45fbeb3c095ed7f/docs/avoid-anonymous-types.md). Original migration linter PR: [Azure/typespec-azure#5551](https://github.com/Azure/typespec-azure/pull/5551).

## 2. Coverage

The comparison reuses the pinned ARM Swagger baseline and reruns the selected TypeSpec linter on the same 487 projects. All 487 workers succeeded; no project is unassessed. Counts below exclude one SDK-only CustomLocations diagnostic absent from the selected Swagger service graph; raw totals are 32 Swagger and 6 TypeSpec diagnostics. Property-owner suppression inspection covers only the nine affected declarations, not exhaustive corpus-wide suppression capture; no corresponding suppressed diagnostics were captured from that unselected owner.

| Count                | Swagger linter | TypeSpec linter |
| -------------------- | -------------: | --------------: |
| Reported diagnostics |             32 |               5 |

**Analysis:** **Assessed coverage** is five directly verified dictionary response contexts: API Management, Developer Hub, HDInsight, and two Network operations. All five produce TypeSpec warnings. For dictionary-valued properties, the existing ARM rule [`arm-no-record`](policy-evidence.md#nested-dictionary-valued-properties) already covers similar cases by rejecting `Record`-typed properties, including nested dictionary declarations. The new response-naming check does not duplicate that restriction. All nine affected property declarations explicitly suppress the existing rule; its exact Swagger correspondence and captured/suppressed diagnostic counts were not measured here. The original source-document attribution of 18 additional Network observations is also unknown, so the diagnostic difference is not a verified count of distinct missing defects or proof of complete Swagger-rule equivalence.

See [Why diagnostic counts differ](#3-why-diagnostic-counts-differ).
