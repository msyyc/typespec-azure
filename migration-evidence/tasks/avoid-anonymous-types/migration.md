# AvoidAnonymousTypes migration

## 1. Conclusion and scope

`@azure-tools/typespec-azure-core/no-unnamed-types` provides **partial, not functionally equivalent**, coverage of the [AvoidAnonymousTypes Swagger linter](https://github.com/Azure/azure-openapi-validator/blob/6243cb01c16c7535cd3b8df6f45fbeb3c095ed7f/docs/avoid-anonymous-types.md). Its policy names authored anonymous types, including implicit HTTP responses, instead of reproducing emitted-schema inlining. Named dictionaries, emission-specific `allOf` and schema overrides remain outside that policy. The existing rule is enabled for both ARM and data-plane services; the response correction adds warnings without an opt-in. **Current external CI fails on one confirmed CustomLocations compatibility warning.** A suppression-only consumer draft proposes preserving that response contract, but is not a validated or landed fix. Current-source Swagger equivalence and green rollout readiness are not established.

## 2. Actual coverage

There are two distinct observations, not a combined comparison population. The historical Swagger comparison assessed **462 successfully compiled ARM projects out of 468**; six failures and their 22 Swagger findings were excluded symmetrically and remain unassessed. Its TypeSpec count belongs to the former **response-only** `tsp-lintdiff-local-linter/avoid-anonymous-types`, not every check in consolidated Core. The current external CI attempted **605 projects: 604 passed and one failed**, reporting one naming warning promoted to an error. It did not run the Swagger linter. Counts below are individual diagnostics, not project counts.

| Count                                                         | Swagger linter | TypeSpec linter |
| ------------------------------------------------------------- | -------------: | --------------: |
| Historical raw diagnostics in the 462 successful projects     |             10 |               1 |
| Current external CI raw diagnostics in 605 attempted projects |        Not run |               1 |

**Assessed coverage:** the 10 historical Swagger findings were classified into three response dictionaries, three nested dictionaries and four dictionary-valued properties literally named `additionalProperties`. The historical TypeSpec-only finding was an anonymous SDK override outside the emitted HTTP operation population. These are explained policy differences, **not 10 missed anonymous source declarations or one matched violation**. Current CI independently confirms the added response check fires on that CustomLocations override at the current linter/compiler revision; its one occurrence maps to one source target and one proposed suppression. Focused tests establish the other declared response behaviors. Neither observation establishes complete source/Swagger correspondence: comparable violation totals, coverage percentages and current-corpus frequencies of emission-specific composition/extension cases remain **unassessed**.

The historical installed-package experiment answers a separate impact question: **469 successful source compiles**, with **21 baseline versus 22 candidate naming warnings**, only CustomLocations added and none removed. Neither that experiment nor the old Swagger run is relabeled as current-head execution. The completed current CI is evidence of the captured warning and failure, not a matched baseline or successful rollout. See [Why diagnostic counts differ](#4-why-diagnostic-counts-differ), [frozen populations](evidence-details.md#assessed-inputs-and-counting) and the [current CI causality report](compatibility.md), which discloses the harness's unrecorded consumer checkout SHA and directly reconciles the diagnosed model with the proposal base.

This table retains the historical **462-project** comparison, not a subtraction against current CI. `raw / grouped` means Swagger diagnostics / distinct project + Swagger-file + JSON-path locations; no occurrences collapse. Grouping does not prove common actionable defects. The TypeSpec column contains response-only findings attributed to the same check and target/context, not unrelated complete-rule warnings. Current CI separately confirms the last row's source-side compatibility effect.

| Difference (with evidence)                                                                                                  | Swagger diagnostics (raw / grouped) | TypeSpec diagnostics for the same check | Recommended action and rationale                                                                                                                                                                                                                                                                    |
| --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------: | --------------------------------------: | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Three response dictionaries](evidence-details.md#dictionary-representation-differences)                                    |                               3 / 3 |                                       0 | Preserve supported named `Record<T>` authoring. Exact schema-inlining parity would need a separate policy decision, not a blanket anonymous-model warning.                                                                                                                                          |
| [Three nested dictionaries](evidence-details.md#dictionary-representation-differences)                                      |                               3 / 3 |                                       0 | Retain the source-naming boundary; do not treat a named generic dictionary as an unnamed declaration.                                                                                                                                                                                               |
| [Four dictionary-valued properties named `additionalProperties`](evidence-details.md#dictionary-representation-differences) |                               4 / 4 |                                       0 | Preserve the dictionary policy. These selector matches are not evidence of four anonymous source-model violations; no upstream-bug disposition is claimed.                                                                                                                                          |
| [CustomLocations SDK override](evidence-details.md#sdk-override-and-compatibility)                                          |                               0 / 0 |                                       1 | [Draft compatibility proposal #48088](https://github.com/Azure/azure-rest-api-specs/pull/48088) adds one operation-scoped suppression to preserve the existing JavaScript response contract. This is a proposed remedy, not approval, validation or landing; the original linter CI remains failed. |

Directional gaps do not cancel: seven historical projects contribute 10 Swagger-only findings and a different project contributes one TypeSpec-only finding. The current CI occurrence is not added to that historical total or treated as a second distinct target. [Composition/extension differences](evidence-details.md#composition-and-extension-boundary) remain non-equivalent with unassessed corpus frequency. No new Swagger comparison or local consumer validation was performed; the [suppression proposal](compatibility.md#suppression-scope) uses completed CI and source/diff evidence only.
