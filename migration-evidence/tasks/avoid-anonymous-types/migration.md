# AvoidAnonymousTypes migration

## 1. Scope

The TypeSpec linter `@azure-tools/typespec-azure-core/no-unnamed-types` is assessed against Swagger linter rule [`AvoidAnonymousTypes`](https://github.com/Azure/azure-openapi-validator/blob/6243cb01c16c7535cd3b8df6f45fbeb3c095ed7f/docs/avoid-anonymous-types.md). Original migration linter PR: [Azure/typespec-azure#5551](https://github.com/Azure/typespec-azure/pull/5551).

## 2. Coverage

The frozen comparison assessed **all 487 ARM projects successfully; none failed or were excluded as projects**. Diagnostics below are individual occurrences for the selected Swagger rule and corresponding TypeSpec checks, not projects or equivalent defects. The source-scope TypeSpec execution recorded ten diagnostics: seven belong to the selected Swagger operation population; one removed-version operation and two SDK-only customizations are [retained but excluded](policy-evidence.md#source-only-observations). No in-scope TypeSpec-only findings were discarded.

| Count                | Swagger linter | TypeSpec linter |
| -------------------- | -------------: | --------------: |
| Reported diagnostics |             32 |               7 |

**Analysis:** **Assessed coverage** now includes five directly verified dictionary response contexts: three ordinary responses plus two Network routes. The TypeSpec linter also reports two selected-version HorizonDB responses that the Swagger linter accepts through external named references. Four nested dictionaries and five dictionary-valued properties named `additionalProperties` remain outside this response-only concrete-instance check; they are not approved retirements. Network contributes another 18 Swagger occurrences for its two reported response paths, with incomplete document-origin attribution. The [full recount](runs/20261117-a00f22c75/recount.json) explains every included occurrence, not an equivalent-defect coverage percentage.

These are configured captured totals, **not an exhaustive suppression-inclusive assessment**. Existing ARM `arm-no-record` suppressions were inspected at the nine dictionary properties, but that owning rule's diagnostics were not captured in this target-only run. No predicted or suppressed owning-rule counts have been added. See [Why diagnostic counts differ](#3-why-diagnostic-counts-differ).
