# AvoidAnonymousTypes migration

## 1. Conclusion and scope

`@azure-tools/typespec-azure-core/no-unnamed-types` provides **partial, not functionally equivalent**, coverage of the [AvoidAnonymousTypes Swagger linter](https://github.com/Azure/azure-openapi-validator/blob/6243cb01c16c7535cd3b8df6f45fbeb3c095ed7f/docs/avoid-anonymous-types.md). It checks authored anonymous TypeSpec types, including implicit HTTP responses, rather than reproducing emitted-schema behavior for named dictionaries, `allOf` or schema overrides. Current-source Swagger correspondence remains unassessed, and a [compatibility validation gate](#notes) remains open.

## 2. Actual coverage

The historical comparison assessed **462 successfully compiled ARM projects out of 468**. Six failed projects and their 22 Swagger findings were excluded from both sides and remain unassessed. Counts are individual diagnostics across the successful projects, not project counts. The TypeSpec column covers the former **response-only** `tsp-lintdiff-local-linter/avoid-anonymous-types`, not the complete consolidated Core rule.

| Count           | Swagger linter | TypeSpec linter |
| --------------- | -------------: | --------------: |
| Raw diagnostics |             10 |               1 |

**Assessed coverage:** the 10 Swagger-only findings were classified as three response dictionaries, three nested dictionaries and four dictionary-valued properties named `additionalProperties`. These named source types are outside the TypeSpec anonymous-type policy. The one TypeSpec-only finding is an authored anonymous SDK response outside the emitted HTTP operation population. Thus the comparison establishes specific policy/scope differences, **not 10 missed anonymous declarations or one matched violation**. Focused regressions support the response-naming behaviors below, but emission-specific composition/extension behavior is not reproduced. Comparable violation totals, coverage percentages and a paired comparison at the current rule/compiler revision remain **unassessed**: the historical inputs differ, and common source/emitted violation identities have not been established.

See [Why diagnostic counts differ](#4-why-diagnostic-counts-differ) for the causes and recommended actions. Historical warning-impact measurements and current rollout CI answer different questions; their results are retained in NOTES and linked evidence, not mixed into this scorecard.

## 4. Why diagnostic counts differ

These are the differing groups in the historical comparison. `raw / grouped` means reported Swagger diagnostics / distinct project + Swagger-file + JSON-path locations; no occurrences collapse, and grouped locations are not proven common defects. The TypeSpec column counts observed response-only diagnostics attributed to that check and target/context, not unrelated Core warnings.

| Difference (with evidence)                                                                                             | Swagger diagnostics (raw / grouped) | TypeSpec diagnostics for the same check | Recommended action and rationale                                                                                                                                         |
| ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------: | --------------------------------------: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Inline response dictionaries](evidence-details.md#dictionary-representation-differences)                              |                               3 / 3 |                                       0 | Not equivalent: the emitted object comes from a named dictionary. Recommend preserving `Record<T>` authoring; schema-inlining parity needs a separate policy decision.   |
| [Inline nested dictionaries](evidence-details.md#dictionary-representation-differences)                                |                               3 / 3 |                                       0 | Not equivalent: the inner dictionary is named in source. Recommend retaining the naming boundary rather than diagnosing a named generic as anonymous.                    |
| [Dictionary-valued properties named `additionalProperties`](evidence-details.md#dictionary-representation-differences) |                               4 / 4 |                                       0 | Not equivalent: the recursive selector reaches named dictionary properties. Recommend preserving the source policy; these observations do not establish an upstream bug. |
| [CustomLocations SDK override](evidence-details.md#sdk-override-and-compatibility)                                     |                               0 / 0 |                                       1 | Covered source behavior, different emitted-operation scope. A suppression is proposed to preserve the SDK contract; approval and validation remain pending.              |

Seven projects contribute the 10 Swagger-only findings, and a different project contributes the TypeSpec-only finding. **Opposing gaps do not cancel.** Additional [composition/extension differences](evidence-details.md#composition-and-extension-boundary) are established by source inspection, not measured corpus frequency. None of these classifications establishes an equivalent defect total or an approved new policy.
