# ARM PUT and resource-response migration

## 1. Conclusion and scope

The TypeSpec linter `@azure-tools/typespec-azure-resource-manager/arm-resource-operation-response` is assessed against [`PutRequestResponseSchemeArm`](https://github.com/Azure/azure-openapi-validator/blob/6243cb01c16c7535cd3b8df6f45fbeb3c095ed7f/docs/put-request-response-scheme-arm.md), [`ConsistentResponseSchemaForPut`](https://github.com/Azure/azure-openapi-validator/blob/6243cb01c16c7535cd3b8df6f45fbeb3c095ed7f/docs/consistent-response-schema-for-put.md), [`XmsResourceInPutResponse`](https://github.com/Azure/azure-openapi-validator/blob/6243cb01c16c7535cd3b8df6f45fbeb3c095ed7f/docs/xms-resource-in-put-response.md), [`PutGetPatchResponseSchema`](https://github.com/Azure/azure-openapi-validator/blob/6243cb01c16c7535cd3b8df6f45fbeb3c095ed7f/docs/put-get-patch-response-schema.md). **Not functionally equivalent to the full Swagger linter policy.** Resource-based checks are implemented, but resolver omissions and unresolved request/cross-method contracts remain. TypeSpec resource identity intentionally replaces extension-presence checking, and the TypeSpec linter avoids the Swagger linter's object-identity bug that reports identical 200/201 references as different. External-specs CI was failing at the assessed revision.

**Assessed coverage:** 208 of 277 original Swagger check contexts are diagnosed: 183 by corresponding configured diagnostics; 25 additional checks by existing owning diagnostics captured before authored suppression. Remaining: 15 confirmed Swagger linter false positives; 19 proposed no-content/collection exclusions awaiting approval; 9 intentional TypeSpec-resource/Swagger-marker differences; 10 checks missed because the resolver omits the PUT; 16 modeling or contract checks still unresolved/deferred. Suppressed diagnostics count toward this assessment, not the configured raw total. Check contexts are not confirmed service defects; equivalent-defect coverage remains unassessed.

One check context identifies a Swagger member, project, resolved document, route and schema comparison; different member checks on the same operation remain distinct. The route row is a population summary, not a count of equivalent defects. See [Why diagnostic counts differ](#4-why-diagnostic-counts-differ) for the causes and recommended actions.

## 4. Why diagnostic counts differ

`Raw / grouped` means individual Swagger findings / distinct check contexts (Swagger member, project, resolved document, route and schema comparison). The TypeSpec column counts configured diagnostics attributed to that same check, not unrelated warnings on the route. Captured diagnostics before suppression are stated separately in the rationale and still count as diagnosed coverage. A diagnostic can cover several check contexts.
