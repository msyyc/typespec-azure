## Causality and exclusions

The existing rule code and default message are insufficient attribution. Request-mismatch and bodyless-PUT checks are new reporting paths; the previous rule did not inspect request bodies. The resolver-based PUT resource-identity pass is also new and reaches existing action/provider responses. For the unchanged canonical message, each target is separately traced through old registration selection/template traversal and the new registration-list/HTTP-payload comparison. Existing DTO/list/result contracts are compatibility exceptions, not permission to rewrite an API solely to silence policy.

Canonical-path dispositions: **confirmed-pr-caused-compatibility: 71**. Seven canonical targets also have a new request/body diagnostic. Annotation eligibility is based on at least one confirmed changed path; a full-code suppression necessarily hides the same rule's other messages at that operation, whose separate disposition remains in JSON.

All 279 observed targets are confirmed PR-caused compatibility findings after source analysis: **0 pre-existing, 0 native false positives, 0 stale and 0 unresolved targets** in this CI sample. These classifications do not establish universal linter equivalence or prove every possible invocation ran. No broad namespace suppression is used.
