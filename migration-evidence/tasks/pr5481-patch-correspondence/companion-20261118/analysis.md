## Why these findings are caused by this PR

At merge-base `8caac67b94bdeff8458617e0fa13fd1664f97990`, the existing `arm-resource-patch` rule has its original subset, tags and superset checks but no name/body listener.
The [PR's rule integration](https://github.com/Azure/typespec-azure/blob/fb7029f43ef7feaf88a8885070f4775d82e42fff/packages/typespec-azure-resource-manager/src/rules/arm-resource-patch.ts) adds the new listener and messages while leaving those checks intact.
All CI messages come from the newly introduced [`arm-resource-patch-body.ts`](https://github.com/Azure/typespec-azure/blob/fb7029f43ef7feaf88a8885070f4775d82e42fff/packages/typespec-azure-resource-manager/src/rules/arm-resource-patch-body.ts) reporting paths: missing body, empty body, or a PATCH writable name absent from the PUT writable input.
Attribution is therefore based on changed reporting paths, not merely a shared rule code.

All CI findings were reconciled to the existing exact-head [source assessment](../names-20261117/assessment.md) and [full diagnostic inventory](../names-20261117/reconciliation.json).
Fetched source locations were checked against every logged declaration excerpt, including files that drifted since the frozen assessment's specs commit `2cd3c5dd6`.
The machine-readable ledger retains the earlier warning identities separately rather than pretending their line numbers are unchanged.
Two identical historical `prefixLimitsDeprecated` messages have ambiguous earlier indices; both candidates are retained and both are excluded, never guessed into an included correspondence.

Their version-aware correspondence remains unresolved under [#5875](https://github.com/Azure/typespec-azure/issues/5875).
They remain in the full occurrence ledger but receive no suppression. This proposal is therefore not a complete external-CI repair.
No included finding is classified as an unchanged/pre-existing reporting path, stale source target, or confirmed native defect.

## Inspection and intentional validation limits

The complete 25-file diff was read and reconciled to the ledger. It contains exactly 62 additions, all full-code `#suppress` directives with backward-compatibility reasons, and no removed or otherwise changed lines.
Removing those exact added directives reproduces every original file byte-for-byte, preserving declarations, comments, existing directives and line endings.
This is source/diff evidence, **not compilation or suppression-execution proof**.
Per the explicit CI-only companion contract, no local consumer compilation, build, tests, lint, formatting, dependency setup, integration or emission was run.
No CI rerun, polling, merge or landing is requested.

The [TypeSpec directive documentation](https://typespec.io/docs/language-basics/directives/#suppress) grounds the full diagnostic code and mandatory justification syntax.
[Machine-readable attribution](attribution.json) preserves all 86 occurrences, exclusions, source identities and the mapping for every added directive.
The main [migration assessment](../migration.md) still measures the original unsuppressed frozen corpus; this separate consumer proposal does not retroactively change its 1,314 / 85 counts.
The existing integrity inventory had six stale entries for already committed report files, listed in the attribution ledger, and omitted 4,465 other already tracked files. Those historical files remain unchanged; refreshing the inventory updates checksum metadata and covers the omitted files. Captured observations are not regenerated or rewritten.
Evidence-repository formatting is scoped to the three changed report files. An initial broad formatter reached archived local cache copies; it was stopped and all 1,283 touched artifacts were restored from the pinned shared baseline, retained fixture/configuration data and the original SHA-verified Markdown renderer. The proposal's consumer checkout was not formatted. Evidence-repository `pnpm lint` reports 13 pre-existing `no-console` warnings in unchanged historical evidence helpers; its subsequent type-aware stage therefore did not run. No JavaScript or TypeScript code is changed by this report update, and those unrelated helpers are left untouched.
