# Documentation quality migration

## 1. Scope

The TypeSpec linter `@azure-tools/typespec-azure-core/documentation-required` is assessed against [DescriptionMustNotBeNodeName](https://github.com/Azure/azure-openapi-validator/blob/main/docs/description-must-not-be-node-name.md) and [DescriptiveDescriptionRequired](https://github.com/Azure/azure-openapi-validator/blob/main/docs/descriptive-description-required.md). Original migration linter PR: [Azure/typespec-azure#5663](https://github.com/Azure/typespec-azure/pull/5663).

## 2. Coverage

No saved combined corpus run measures the official rule at the assessed revision. Each historical member investigation attempted **468 ARM projects**, with **462 successful compilations and 6 exclusions**, but the two TypeSpec runs used different source/closure revisions. They cannot be combined into an official-rule total.

| Count                | Swagger linter | TypeSpec linter |
| -------------------- | -------------- | --------------- |
| Reported diagnostics | Unassessed     | Unassessed      |

Reported diagnostics means individual findings for the two original Swagger checks, including corresponding captured suppressed findings, not project counts or the mixed rule's existing missing-documentation warnings. The historical runs honored source suppressions; no separate pre-suppression diagnostic capture is available. Additional suppressed findings are therefore **unassessed, not zero**.

**Analysis:** The historical name-check run recorded **70,815 Swagger findings and 7,523 TypeSpec findings**; all 105 Swagger-affected projects were among the 143 TypeSpec-affected projects. The blank-check run recorded **0 and 5**, and all five TypeSpec findings were investigated. These observations explain specific source/emission differences, not current combined coverage: the official rule now compares authored ordinary-property names instead of JSON serialization names. Its focused tests cover that adaptation, but its corpus impact and a comparable-defect coverage percentage remain unassessed.

The separate CI compatibility sample is not a Swagger comparison and is not added to these totals. See [Why diagnostic counts differ](#3-why-diagnostic-counts-differ) for the historical arithmetic, attribution limits and proposed actions.

## 3. Why diagnostic counts differ

The official combined difference is **unassessed**. The table below describes the **separate historical successful-project runs only**: TypeSpec values are configured diagnostics for the named quality check, with uncaptured suppressed additions unassessed. Existing missing-documentation `default` warnings are outside this comparison. Historical values are not relabeled as the official rule's suppression-inclusive totals.

| Difference (with evidence)                                                                                                                     | Swagger diagnostics | TypeSpec diagnostics for the same check           | analysis                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Historical name-check source/emission differences](members/DescriptionMustNotBeNodeName/migration.md#3-why-diagnostic-counts-differ)          | 70,815              | 7,523 configured; suppressed additions unassessed | Repeated references, inline copies, emitted names and source-only declarations use different identities. Preserve semantic source targets rather than reproducing every emitted occurrence. Exact per-cause diagnostic attribution and the official authored-name change's corpus impact remain unassessed. |
| [Four empty fields skipped by the Swagger selector](members/DescriptiveDescriptionRequired/migration.md#3-why-diagnostic-counts-differ)        | 0                   | 4 configured                                      | The selector's truthy precondition skips `description: ""`, a confirmed false-negative bug. Retain the TypeSpec blank checks rather than copy the bug.                                                                                                                                                      |
| [Empty inherited-property description omitted on emission](members/DescriptiveDescriptionRequired/migration.md#3-why-diagnostic-counts-differ) | 0                   | 1 configured                                      | Effective authored documentation is empty but no description field is emitted. Retain the source check; emitted-field absence does not establish meaningful documentation.                                                                                                                                  |

**Raw-count reconciliation:** The historical name-check configured difference is **`70,815 - 7,523 = 63,292`**. Selected-version attribution removes 22 TypeSpec findings, leaving 7,501; that is a different population, not the original raw count. The available investigations identify causes and concrete examples, but do not partition the entire 63,292 difference into proven per-cause contributions. That attribution remains **unassessed**, not 63,292 proven missing checks.

The historical blank-check configured difference is fully explained: **`0 - 5 = -4 - 1 = -5`**. The two historical differences must not be summed: their TypeSpec source/closure revisions differ, suppressed additions were not captured, and neither run measures the consolidated rule. Consequently there is no supported current combined net gap to reconcile. [Detailed populations, exclusions and examples](evidence-details.md#historical-populations-and-exclusions) retain the original data.
