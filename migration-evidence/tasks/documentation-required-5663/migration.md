# Documentation quality migration

## 1. Scope

The TypeSpec linter `@azure-tools/typespec-azure-core/documentation-required` is assessed against [DescriptionMustNotBeNodeName](https://github.com/Azure/azure-openapi-validator/blob/main/docs/description-must-not-be-node-name.md) and [DescriptiveDescriptionRequired](https://github.com/Azure/azure-openapi-validator/blob/main/docs/descriptive-description-required.md). Original migration linter PR: [Azure/typespec-azure#5663](https://github.com/Azure/typespec-azure/pull/5663).

## 2. Coverage

The November 18 native run assessed **all 490 frozen ARM projects**, with **zero compilation failures or exclusions**, against the verified shared Swagger baseline. Both quality checks ran together using the official PR implementation, including its authored-property-name policy.

| Count                | Swagger linter | TypeSpec linter |
| -------------------- | -------------- | --------------- |
| Reported diagnostics | 88,500         | 8,387           |

These are individual diagnostic occurrences, not equivalent defects. TypeSpec comprises **7,852 configured + 535 captured suppressed** findings: **8,355 name-check findings** (7,852 + 503) and **32 blank-check findings** (0 + 32). Pre-suppression observation covers every successful program and reconciles the configured diagnostic multiset. The existing missing-documentation check contributes **11,260 additional captured suppressed diagnostics**, excluded from both migrated checks. No proposed companion annotations are added to these counts.

**Assessed coverage:** Native execution and suppression accounting are complete for 490/490 projects. All **107 Swagger name-check projects** have corresponding name-check findings at project level; TypeSpec reports that family in **149 projects**, with 42 TypeSpec-only projects. Blank checks report 32 findings at 10 source locations in four projects versus zero Swagger findings. [Scoped accounting](runs/native-20261118/scoped-summary.json), [complete project counts](runs/native-20261118/per-project-counts.json), and [captured quality diagnostics](runs/native-20261118/native-quality.jsonl) retain the evidence.

**Analysis:** The rule demonstrably executes both migrated checks and the reviewed authored-name adaptation. Project overlap is not defect correspondence: source programs contain all declared versions and imported/client-only declarations, while Swagger selects emitted versions and repeats reference contexts. Exact comparable-defect coverage and exhaustive causal allocation remain **unassessed**, not zero or a percentage. See [Why diagnostic counts differ](#3-why-diagnostic-counts-differ) and the [investigation](evidence-details.md#current-count-investigation).

Retain blank checks rather than reproduce the selector's empty-string false negative.              |

**Raw-count reconciliation:** **`88,500 - 8,387 = (65,199 - 613) + (17,221 - 936) + (6,080 - 6,806) + (0 - 32) = 80,113`**. Name checks alone differ by 80,145. Their per-project positive excess is **81,167** and negative excess **1,022**; after adding blank checks, the combined directional excesses are **81,140** and **1,027**. Neither cancellation nor grouped paths establishes matched defects.

**Unresolved causal allocation:** The measured 80,145 name-check difference is not fully assigned to proven causes; 27 blank findings lack an exact source-to-emission partition. In particular, 80,659 Swagger name observations use input-fallback attribution rather than a reported source document. The [full witness inventory](runs/native-20261118/investigation.json) and [replay instructions](runs/native-20261118/README.md) preserve those limits. No linter behavior change or migration-acceptance conclusion follows merely from the count gap.
