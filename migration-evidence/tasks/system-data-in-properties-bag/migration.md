# SystemDataInPropertiesBag migration

## 1. Conclusion and scope

The TypeSpec rule `@azure-tools/typespec-azure-resource-manager/no-reserved-resource-property` provides **partial coverage**, not functional/output equivalence, for Swagger rule [SystemDataInPropertiesBag](https://github.com/Azure/azure-openapi-validator/blob/e1b8b207a196cf2fc288593efec22e6e38ab98d5/docs/system-data-in-properties-bag.md). Its approved policy checks immediate and inherited authored-name members of recognized ARM resource properties bags, case-insensitively. Arbitrary recursion, JSON aliases and non-resource bags are outside this policy; nested metadata is not universally declared compliant. The TypeSpec linter intentionally does not reproduce the Swagger helper's first-child early-return bug, which can miss a genuine direct-bag violation.

## 2. Actual coverage

The final synchronized-source run assessed **487/487 projects**, with zero failures, unassessed projects or ambient compiler errors. Reported diagnostics are total individual findings across that population, not project counts.

| Count                | Swagger linter | TypeSpec linter |
| -------------------- | -------------: | --------------: |
| Reported diagnostics |              0 |               1 |

**Assessed coverage:** immediate and inherited ARM resource-bag checks are supported by canonical tests and actual-package controls. The one observed TypeSpec warning is a source/schema-verified direct `systemData` violation in DataBoxEdge; the shared rule contributes zero `billingData` or other warnings. Every project's exact target/message, aligned diagnostics and default-configured warnings match the preceding 487-project run. One older recursive embedded-envelope warning remains intentionally retired, not a current missing finding.

Arbitrary recursive searches, JSON-alias matching and non-resource definition bags remain outside the approved policy. Comparable cross-engine violation totals and coverage percentages are **unassessed**: the corpus has zero Swagger-positive findings and no complete semantic-correspondence mapping. Neither 487 successful assessments nor a raw 0/1 score establishes exhaustive coverage or parity. The remaining observed difference is explained by the pinned Swagger helper's false-negative bug; see [Why diagnostic counts differ](#4-why-diagnostic-counts-differ).
