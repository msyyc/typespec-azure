# LatestVersionOfCommonTypesMustBeUsed migration

## 1. Conclusion and scope

The TypeSpec rule `@azure-tools/typespec-azure-resource-manager/arm-common-types-version` covers the **approved latest-API-version selection policy**, a deliberately narrower recovery of Swagger linter rule [`LatestVersionOfCommonTypesMustBeUsed`](https://github.com/Azure/azure-openapi-validator/blob/6243cb01c16c7535cd3b8df6f45fbeb3c095ed7f/docs/latest-version-of-common-types-must-be-used.md). It checks the last declared API-version member, with stable and preview on one timeline, while preserving all-version explicit-configuration checks and unversioned-service guidance. **It is not functionally equivalent to the full Swagger reference checker:** emitted legacy references and per-filename version policy remain outside this recovery.

## 2. Actual coverage

All **487** selected ARM projects were assessed successfully; **zero** projects failed or remain unassessed. Reported diagnostics are individual findings across that population, not project counts.

| Count                | Swagger linter | TypeSpec linter |
| -------------------- | -------------: | --------------: |
| Reported diagnostics |         65,786 |             388 |

**Assessed coverage:** the TypeSpec linter observed **381 outdated-selection warnings** and **7 existing missing-explicit-configuration warnings**. Focused and injected controls establish the requested latest-only, inheritance/override, declaration-order, historical-gap, suppression, and unversioned behavior. The ten Swagger-only projects, comprising **117 reference findings**, are individually assessed as compliant latest selections with filename/legacy-reference differences, or existing authored suppression. No TypeSpec-only project was observed. This supports the approved selection/configuration policy; it does not establish coverage of every emitted reference. Comparable violation totals and coverage percentages remain **unassessed**, because no tested common identity maps the reference findings to source-selection/configuration defects.

The comparison explicitly enables the rule: actual project defaults produce **379**, not 388, warnings because nine projects disable it in configuration. Source suppressions remain honored. The seven configuration warnings are not attributed as counterparts of Swagger reference findings. See [Why diagnostic counts differ](#4-why-diagnostic-counts-differ) for the complete accounting and limits.

## 4. Why diagnostic counts differ

The following are complete, nonoverlapping **observation groups**, not normalized violations. Counts are Swagger / TypeSpec findings in the group's projects; reference-to-source correspondence remains unassessed. The [grouped investigation](migration-evidence/arm-common-types-latest-api-version/differences.md) supplies exact causes, coverage status, recommended actions, and source/schema examples.

- **381 projects: 64,960 / 381.** [Reference occurrences versus source selection](migration-evidence/arm-common-types-latest-api-version/differences.md#reference-occurrences-versus-source-selection): many emitted references can accompany one outdated selection. Upgrade the latest selection subject to service compatibility review, not historical contracts merely to equalize counts.
- **7 projects: 709 / 7.** [Existing configuration check](migration-evidence/arm-common-types-latest-api-version/differences.md#existing-configuration-check): these TypeSpec warnings concern missing explicit configuration, a different predicate. Configure all versions before assessing outdated guidance; do not count these as matched references.
- **10 Swagger-only projects: 117 / 0.** [Individually inspected differences](migration-evidence/arm-common-types-latest-api-version/differences.md#all-ten-swagger-only-projects): filename-map differences **7 / 0**, deprecated location-parameter references **7 / 0**, explicit legacy identity **2 / 0**, and authored DatabaseWatcher suppression **101 / 0**. Keep the approved boundary; any upstream policy or service compatibility change needs separate owning review.

Network and SQL are the largest raw-count outliers. [Their saved-path investigation](migration-evidence/arm-common-types-latest-api-version/differences.md#outliers-and-originating-document-limits) shows reference reuse and repeated input associations, while retaining missing originating-document attribution. Neither inferred origins nor deduplicated paths are promoted to matched service defects. There is no unexplained project-count residual; exact semantic correspondence remains unassessed rather than invented.
